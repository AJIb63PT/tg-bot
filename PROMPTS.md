# Промпты для воспроизведения проекта

Документ описывает, **какие промпты нужно было задать**, чтобы получить текущий
результат — Telegram-бот учёта задач на Node.js + SQLite, без npm-зависимостей.

Разбор построен по фактической истории работы: сначала идёт сводный промпт, который
закрыл бы почти всё сразу, затем промпты изменений объёма, затем — то, что промптом
быть не должно.

---

## Часть 1. Сводный промпт (закрыл бы ~80% работы)

> Сделай Telegram-бота учёта задач для строительного участка.
>
> **Стек:** Node.js 22.5+ и **только встроенные модули**, без npm-зависимостей.
> Хранилище — SQLite через `node:sqlite`. Google Таблицы не использовать.
>
> **Ввод.** Пользователь пишет задачу обычным сообщением:
> `Покраска, заказ 123, срок пятница, ответственный Иван, участок ФФ1`
> Бот сам разбирает: участок, заказ, срок, ответственного, вид работ, название.
> Сроки понимать по-русски: «завтра», «пятница», «15 ноября», «через 3 дня»,
> «до конца месяца», «срочно», «14:30», «без срока». Несколько строк в одном
> сообщении = несколько задач.
>
> **Хранение.** Всё в одном файле SQLite. Схему продумай сам: задачи, участки,
> настройки чата, кэш прогнозов, журнал изменений.
>
> **Сводка.** Каждое утро в 09:00 по часовому поясу из `.env` присылать: просрочено,
> на сегодня, завтра, до конца недели. Отправлять строго один раз в день. Если
> процесс был выключен и время прошло — догонять запуск, но не позже чем через
> 3 часа, чтобы вечером не приходило «утреннее» сообщение.
>
> **Погода.** Через Open-Meteo (ключ не нужен). Предупреждать о морозе ниже порога,
> сильном ветре и дожде — для уличных работ вида «монтаж», «кровля», «бетон»,
> «фасад», «сварка». Прогнозы кэшировать, чтобы не дёргать API лишний раз.
> Сбой погоды не должен ломать ни приём задач, ни сводку.
>
> **Пороги и настройки** — только в `.env`: `FROST_THRESHOLD_C`, `WIND_THRESHOLD_KMH`,
> `RAIN_THRESHOLD_MM`. Меняются файлом и перезапуском.
>
> **Участки.** Участок заводится в справочник автоматически, как только упомянут
> в задаче — **независимо от того, нужна ли работе проверка погоды**. После этого
> бот должен узнавать участок в тексте и без метки, в том числе в косвенном падеже
> («в цехе 2» → `Цех 2`), и **вырезать его из названия задачи**.
>
> **Команды:** `/list`, `/today`, `/overdue`, `/week`, `/find`, `/card`, `/done`,
> `/undone`, `/cancel`, `/del`, `/assign`, `/due`, `/setarea`, `/areas`, `/digest`,
> `/summary`, `/export`, `/id`, `/help`. Команд управления погодой **не делать**.
>
> **Кнопки.** В списках задач — ровно две кнопки на задачу: «выполнено» и «перенести
> на день». Больше ничего. Карточка задачи открывается командой `/card`; внутри неё
> кнопки выполнить, перенести на день/неделю, вернуться к списку, удалить.
>
> **Доступ.** Белый список Telegram ID из `.env`. Пустой — доступ всем (для отладки).
>
> **Требования к качеству:**
>
> - тесты на разбор текста, работу с базой, пороги погоды, логику «сводка раз в день»,
>   все команды и **все кнопки**;
> - проверь работу с **кириллицей** в поиске и сравнении строк;
> - `README.md` из трёх разделов: (0) краткое описание функционала, (1) схема
>   архитектуры на одну страницу — что с чем общается, где хранятся данные, что делать
>   при недоступности сервисов, (2) 5–7 строк о переходе на Bitrix24;
> - всё описание архитектуры сверяй с фактическим кодом, а не по памяти.

## Часть 2. Промпты изменений

Эти промпты **нужны** — это осознанные решения по объёму, их нельзя было угадать.

> Убери функционал, отвечающий за Google Таблицы. Работаем только на SQLite.
> CSV-выгрузку оставь.

### Промпт 3. Убрать команды управления погодой

> В `/list` оставь только две кнопки: «выполнено» и «перенести».

### Промпт 5. Переписать README

## Часть 3. Чек-лист приёмки

Как проверить, что результат соответствует замыслу:

```
npm test          → все тесты проходят (сейчас 86)
npm run test:net  → то же + реальный запрос к Open-Meteo
npm run digest    → сводка с погодными рисками
```

Проверить руками:

- [ ] Сообщение `Покраска, заказ 123, срок пятница, ответственный Иван, участок ФФ1`
      создаёт задачу, участок попадает в `/areas`, название — без лишних запятых.
- [ ] Повторное сообщение с `ФФ1` без метки узнаёт участок и убирает его из названия.
- [ ] В `/list` ровно две кнопки, обе работают.
- [ ] Команды управления погодой отвечают «Неизвестная команда».
- [ ] `/export` отдаёт CSV, открывающийся в Excel.
- [ ] Отключить интернет — задачи и сводка продолжают работать, погодный блок
      сообщает об ошибке, но не ломает сообщение.

## Состав результата

12 модулей в `src/`, 6 файлов тестов, 7 таблиц SQLite, README из трёх разделов.
Никаких npm-зависимостей: Telegram Bot API и Open-Meteo вызываются через встроенный
`fetch`, база — через `node:sqlite`, JWT для Google больше не нужен.
